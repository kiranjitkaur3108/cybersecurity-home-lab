## 2. Connectivity Test

After configuring the network, I verified connectivity between Kali Linux and Ubuntu using ICMP.

From Kali Linux, I ran:

```bash
ping -c 5 192.168.56.10
```

### Result

```text
5 packets transmitted
5 packets received
0% packet loss
```

This confirmed successful network connectivity between Kali Linux and Ubuntu.

### Communication Flow

```text
Kali
192.168.56.11
      |
      | ICMP Echo Request
      v
Ubuntu
192.168.56.10
      |
      | ICMP Echo Reply
      v
Kali
```

---

## 3. Wireshark Packet Capture

I used Wireshark on Kali Linux to capture and analyze the traffic generated by the ping.

The capture was performed on the network interface connected to the VirtualBox Internal Network.

I generated ICMP traffic using:

```bash
ping -c 5 192.168.56.10
```

I then used the following Wireshark display filter:

```text
icmp
```

This allowed me to isolate ICMP packets from other network traffic.

---

## 4. ICMP Packet Analysis

The Wireshark capture showed ICMP Echo Requests and Echo Replies.

### Echo Request

```text
Kali → Ubuntu
ICMP Echo Request
Type: 8
Code: 0
```

### Echo Reply

```text
Ubuntu → Kali
ICMP Echo Reply
Type: 0
Code: 0
```

The IPv4 header allowed me to observe the source and destination IP addresses.

For example, the reply packet contained:

```text
Source:      192.168.56.10
Destination: 192.168.56.11
```

### Important ICMP Types

| ICMP Type | Meaning |
|---|---|
| `8` | Echo Request |
| `0` | Echo Reply |

---

## 5. Understanding the Captured Packet

The captured packet contained several protocol layers:

```text
Ethernet II
     ↓
IPv4
     ↓
ICMP
```

### Ethernet

The Ethernet layer contains information used for communication on the local network, including MAC addresses.

### IPv4

The IPv4 layer contains information such as:

- Source IP address
- Destination IP address

In this lab:

```text
Kali:   192.168.56.11
Ubuntu: 192.168.56.10
```

### ICMP

ICMP was used by the `ping` command to test connectivity.

The request and response verified that the two virtual machines could communicate successfully.

## 6. Initial Nmap Service Detection

From Kali Linux, I performed an initial Nmap service/version scan against the Ubuntu VM.

Command used:

```bash
nmap -sV 192.168.56.10
```

### Initial Result

The Ubuntu host was detected as:

```text
Host is up
```

The scan reported that the default 1,000 TCP ports scanned by Nmap were closed.

The initial result was approximately:

```text
1000 scanned TCP ports
1000 closed
```

No open services were detected in the initial scan.

### What does `-sV` mean?

The `-sV` option enables **service/version detection**.

Nmap attempts to determine:

- Which services are running
- Which ports are open
- What service is associated with an open port
- The version of the detected service when possible

A test TCP service will be configured on Ubuntu later in this lab so that Nmap can detect an open port.
